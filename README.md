# Smart Document Search — ИИ-поиск по документам (иврит, RTL)

WordPress-плагин для сайта юридической фирмы: загружаете решения судов (.doc, .docx, .pdf, .txt),
плагин индексирует их, а посетители задают вопросы на иврите и получают короткий ответ,
составленный **только** по найденным фрагментам, со списком источников.

- Автор: Oleg Gendelman · Версия: 1.0.0 · PHP 7.4–8.3 · WordPress 5.8+
- Работает на обычном shared-хостинге: чистый PHP, без exec(), antiword, LibreOffice и Composer на сервере.
- ИИ: OpenAI API (ключ клиента). Эмбеддинги `text-embedding-3-small`, ответы `gpt-4o-mini` (меняется в настройках).

---

## 1. Установка

1. Скачайте `dist/smart-document-search.zip` (или соберите: `./build.sh`, см. раздел 6).
2. WordPress → Плагины → Добавить новый → Загрузить плагин → выберите zip → Установить → Активировать.
3. Требования к серверу: PHP 7.4+ с расширениями `mbstring`, `zip` (для .docx), `json`, `zlib`.
   `sodium` желательно (если его нет, WordPress подставляет встроенный `sodium_compat`).
4. При активации создаются таблицы `wp_hds_docs`, `wp_hds_chunks` и папка
   `wp-content/uploads/hds-docs/`, закрытая от прямого доступа (`.htaccess` deny, `index.php`, `web.config`).

> **Nginx:** `.htaccess` на nginx не действует. Добавьте в конфиг сайта:
> ```nginx
> location ^~ /wp-content/uploads/hds-docs/ { deny all; return 403; }
> ```
> Имена файлов дополнительно содержат случайный суффикс, их нельзя угадать.

## 2. Ключ OpenAI — в `wp-config.php`

Рекомендуемый способ — константа (ключ не хранится в базе и не виден в админке).
Откройте `wp-config.php` и **над** строкой `/* That's all, stop editing! */` добавьте:

```php
define( 'HDS_OPENAI_KEY', 'sk-...ключ клиента...' );
```

Запасной вариант — поле «OpenAI API key» на странице **AI Search → Settings**. Ключ из поля хранится
в базе зашифрованным (libsodium, ключ шифрования выводится из солей `wp-config.php`), обратно на
страницу никогда не выводится (только маска) и никогда не передаётся на фронтенд.
Если константа задана, поле не показывается. Кнопка **Test connection** проверяет ключ.

## 3. Работа в админке (меню «AI Search», только для администраторов)

- **Documents** — загрузка нескольких файлов сразу (.doc, .docx, .pdf, .txt; проверяются расширение,
  сигнатура файла и MIME; лимит размера — в настройках), таблица документов (название, размер,
  статус, число фрагментов, удаление, переименование).
- **Update index** — индексация пакетами через AJAX с прогресс-баром (каждый шаг ≤ 20 с, чтобы не
  упираться в `max_execution_time`). Неизменившиеся файлы (sha256) пропускаются без затрат на API.
  Битый файл помечается ошибкой и не останавливает остальные. PDF без текстового слоя помечается
  «Scanned PDF – no text found» (OCR не выполняется).
- **Settings** — модель эмбеддингов, модель ответа, число фрагментов в контексте, лимит запросов
  в минуту с одного IP, максимальный размер файла, лицензионный ключ, запасное поле ключа OpenAI.

После смены модели эмбеддингов нажмите **Update index** — векторы пересчитаются.

## 4. Поиск на сайте

- Шорткод: `[hds_search]` (параметр `placeholder="..."`), или блок Gutenberg **AI Search**.
- Подсказки при вводе (после 2 символов) — по названиям документов и частым фразам из них,
  **без обращения к OpenAI** (словарь собирается при индексации).
- Enter → REST `POST /wp-json/hds/v1/ask` (с nonce) → эмбеддинг вопроса → косинусная близость по всем
  фрагментам → топ-N фрагментов → короткий ответ на иврите (2–4 предложения) только по ним.
  Если ответа нет — так и пишется. Под ответом — источники с подсветкой слов запроса и пометка,
  что это не юридическая консультация.
- Повторные вопросы отвечаются из кэша (сутки) — без расходов на API. Лимит запросов по IP.
- Вёрстка RTL, наследует шрифт и цвета темы, адаптив, доступность (label, aria-live, клавиатура).

## 5. Демо-режим и лицензия

Пока не введён валидный лицензионный ключ, плагин работает в **демо-режиме** — открыто и честно:

- индексируются **первые 15 документов** (по дате загрузки); остальные помечаются
  «Available in the full version»;
- в форме поиска маленькая метка **Demo**; в админке — ненавязчивое уведомление «Demo version»;
- всё остальное работает полностью.

Проверка ключа **полностью локальная**: подпись Ed25519 (libsodium) домена сайта, в плагине хранится
только публичный ключ. Никаких запросов на внешние серверы, никаких таймеров, дат и удалённого
отключения; без ключа плагин просто остаётся в демо. Скрытых функций нет.

Домен берётся из `home_url()` без протокола, `www.`, порта и пути: `https://www.example.co.il/` →
`example.co.il`. Каждый домен подписывается отдельно, поэтому ключ для `staging.example.co.il`
не подходит для `example.co.il` и наоборот.

### Как выдать лицензию (на вашем компьютере, не на сервере)

Скрипт `tools/keygen.php` **не входит** в zip плагина. Нужен PHP с расширением sodium.

```bash
# 1. Один раз: создать пару ключей
php tools/keygen.php init
#    → приватный ключ сохранён в tools/private.key (в .gitignore, СДЕЛАЙТЕ РЕЗЕРВНУЮ КОПИЮ!)
#    → печатается строка для вставки в includes/class-hds-license.php:
#      const PUBLIC_KEY = '...';
#    Вставьте её, затем соберите zip: ./build.sh --require-license-key

# 2. Для каждого сайта клиента: подписать домен
php tools/keygen.php sign example.co.il
php tools/keygen.php sign staging.example.co.il   # отдельный ключ для staging

# 3. Проверить ключ
php tools/keygen.php verify example.co.il <ключ>
```

Клиент вставляет ключ в **AI Search → Settings → License key**. Там же показан «Site domain for
licensing» — ровно та строка, которую нужно подписать.

> Если потерять `tools/private.key`, новые ключи выдать будет нельзя — придётся создать новую пару и
> выпустить обновление плагина с новым публичным ключом (старые ключи перестанут подходить).

## 6. Сборка zip

```bash
./build.sh                         # dist/smart-document-search.zip
./build.sh --require-license-key   # то же, но ошибка, если PUBLIC_KEY не вставлен
```

В архив не попадают `tools/`, `tests/`, `.git`, Composer/npm-файлы, скрипты сборки, README.md.
Скрипт проверяет, что в архиве нет приватного ключа, и прогоняет `php -l` по всем файлам.

## 7. Разработка и тесты

```bash
composer install                   # dev-зависимости в .dev/vendor (PHPUnit, исходник pdfparser)
php tools/prefix-vendor.php        # пересобрать vendor/ (smalot/pdfparser с префиксом HDS_Vendor\)
.dev/vendor/bin/phpunit            # юнит-тесты (без WordPress)
php tests/print-fixtures.php       # первые 500 символов текста каждого тестового файла
tests/fixtures/generate.sh         # пересоздать .docx/.pdf/.txt-фикстуры (нужны LibreOffice, python3)
cd tests/e2e && npm ci && ./run.sh # e2e: @wordpress/env + Playwright (нужен Docker)
```

E2E без переменной `OPENAI_API_KEY` использует мок OpenAI (mu-plugin только для тестового окружения);
с `OPENAI_API_KEY=sk-... ./run.sh` — реальный API.

### Структура

```
smart-document-search.php     шапка плагина, константы, хуки активации
uninstall.php                 удаляет таблицы, опции, transients и папку hds-docs
includes/                     ядро: настройки, лицензия, хранилище, индексатор, поиск, REST, шорткод/блок
includes/extractors/          .doc (собственный парсер CFB/OLE2 + Word 97), .docx, .pdf, .txt
admin/                        страницы админки и AJAX
assets/                       JS/CSS (без сборки), блок Gutenberg на чистом wp.blocks
vendor/                       smalot/pdfparser с префиксом namespace (LGPL-3.0)
tools/  tests/                только для разработки, не входят в zip
```

## 8. Конфиденциальность

- Тексты документов и запросы пользователей не логируются.
- В OpenAI отправляются фрагменты документов (при индексации и в контексте ответа) и вопросы
  посетителей — это нужно учесть в политике конфиденциальности сайта.
- IP-адреса для лимита запросов хранятся только в виде хэша, 60 секунд.
